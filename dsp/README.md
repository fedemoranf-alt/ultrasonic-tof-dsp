# `dsp/` — host-testable DSP kernels

The signal-processing core of the ultrasonic time-of-flight platform, extracted
from the firmware so it can be compiled and tested on a PC with no board
attached, and run automatically on every commit.

The algorithms themselves are the ones that run on the ESP32 in
[`firmware/esp32/src/main.cpp`](../firmware/esp32/src/main.cpp). What changed is
what they depend on: no globals, no fixed `#define`d buffer sizes, no Arduino
headers. Lengths are parameters and every buffer is supplied by the caller.

## Why this exists

Time-delay estimation is easy to get subtly wrong. A cross-correlation whose lag
convention is off by one still produces a smooth, plausible-looking distance
reading — it is just wrong by one sample, which at this sample rate is a large
error. That class of bug does not announce itself on an oscilloscope, and it is
expensive to find on hardware.

So the parts that can be checked without hardware are checked without hardware,
on every push.

## Running the tests

```sh
make test        # build and run
make strict      # same, but any compiler warning is a hard error
make sanitize    # same, under AddressSanitizer + UndefinedBehaviorSanitizer
make clean
```

Requires a C99 compiler and `make`. On Windows with the WinLibs/MinGW toolchain
the command is `mingw32-make` rather than `make`, and `make sanitize` is not
available there — MinGW does not ship libasan/libubsan, so that target links
only on Linux and macOS. It runs in CI, which is where it matters.

Passing output ends with:

```
  9 tests, 9 passed, 0 failed, 249 individual checks
ALL TESTS PASSED
```

and a zero exit code. A failure prints the file and line, the expected and
actual values, the difference, and the loop index if the check was inside a
loop — then exits non-zero so CI notices.

## What is covered

| Test | What it pins down |
|---|---|
| `fir_impulse_response` | The impulse response of the FIR is its own tap vector. |
| `fir_dc_gain_and_transients` | Unity gain at DC after a 3-sample transient, with a matching tail — catches off-by-one errors in the accumulation loop. |
| `xcorr_hand_computed` | The correlation of `[1 2 3]` with `[1 1]` is `[1 3 5 3]`, worked out by hand in the test's own comment. Pins the lag convention. |
| `tof_lag_recovers_known_delay` | A windowed burst hidden in noise at a known offset is recovered at exactly that offset, and the peak dominates everything outside its main lobe. |
| `envelope_of_quadrature_pair` | The envelope of `A·cos` and `A·sin` is `A` everywhere — a ripple here means the Hilbert branch is misaligned. |
| `remove_dc` | Zero mean afterwards, and every sample shifted by the same amount. |
| `upsample_zero_stuffing` | Input samples land on multiples of M, zeros elsewhere, correct output length. |
| `argmax_tie_goes_to_first` | Ties resolve to the lowest index, which the lag arithmetic downstream assumes. |
| `normalize_peak` | Peak becomes 1, and an all-zero frame stays zero instead of turning into NaN and propagating silently into the distance reading. |

Every expected value above is derivable by hand, or is a property that must hold
for any correct implementation. None of it was produced by running the code and
recording whatever came out — that only locks in today's behaviour, bugs
included.

The test signals are generated by a fixed-seed LCG rather than `rand()`, so the
result is identical on any machine. A test that fails once a fortnight is worse
than no test at all.

## What is *not* covered

The PSoC Creator project and the PlatformIO build are not compiled here. Neither
is the acquisition path — ADC, DMA, UART, WiFi — which needs the board. This
directory covers the arithmetic, which is the part where a silent error is both
most likely and hardest to see on the bench.

## Adding a test

Add a `static void test_something(void)` to `tests/test_dsp.c`, bracket it with
`check_begin("something")` and `check_end()`, and call it from `main()`. The
available checks are `CHECK_TRUE`, `CHECK_NEAR`, `CHECK_NEAR_AT` (reports the
loop index too) and `CHECK_LONG_EQ`; `check_dump()` prints a window of samples
around an index for context after a failure.

## Layout

```
dsp/
├── dsp.h              public API, one comment block per function
├── dsp.c              the kernels
├── Makefile           test / strict / sanitize / clean
└── tests/
    ├── check.h        the test macros
    ├── check.c        the harness (~180 lines, no dependencies)
    └── test_dsp.c     the tests
```
